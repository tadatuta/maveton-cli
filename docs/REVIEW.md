# Ревью реализации

Дата: 6 ноября 2026 года. Область: Podcasting 2.0, локальная валидация и безопасное добавление в существующий RSS. Все перечисленные ниже дефекты исправлены и покрыты регрессионными сценариями.

## Существенные дефекты сохранения

| Проблема до исправления | Исправление |
| --- | --- |
| Повышение explicit канала с false до true меняло эффективную маркировку старых эпизодов без собственного explicit | Им явно назначается false, включая liveItem; число изменений отражается в explicitPreserved |
| Входной YAML/JSON через symlink можно было затереть записью по реальному пути | Сравниваются целевые inode; проверка повторяется перед сохранением |
| Изменения исходника во время подготовки результата могли остаться незамеченными | Исходный RSS повторно читается непосредственно перед заменой; выход сравнивается по байтам и метаданным, включая ctime |
| Резервная копия повторно открывала путь вместо использования проверенного содержимого | Backup создаётся из байтов проверенного файлового дескриптора и синхронизируется до замены |
| Ошибка после атомарной замены выглядела как обычный отказ записи | OUTPUT_COMMITTED явно сообщает, что результат уже записан |
| Сбой одной операции очистки мог помешать остальным | Все операции очистки предпринимаются независимо; исходная ошибка сохраняется |
| add мог скрыть неверный lastBuildDate заменой на текущую дату | Исходный фид валидируется до изменения, результат — перед записью |
| Неудачное добавление могло частично изменить переданный DOM | Работа ведётся с копией DOM; коллизии GUID проверяются также с liveItem |

## Дефекты XML и валидации

- Толерантный DOM-парсер мог потерять атрибуты с одинаковым полным именем при разных префиксах. Перед DOM добавлен строгий SAX-разбор с проверкой namespace, глубины, сущностей и well-formedness.
- Регулярное выражение ошибочно запрещало упоминание DOCTYPE внутри комментария/CDATA. Теперь блокируется именно DTD, распознанный XML-парсером.
- Проверка родителей Podcasting 2.0 сравнивала только локальное имя: тег внутри постороннего `value` мог пройти. Теперь учитывается namespace родителя.
- Проверяются недопустимые ненamespace-элементы RSS в channel/item/liveItem, пустые опциональные поля, содержимое атрибутных enclosure/image, MIME основного live-enclosure и корректность permalink GUID. Диагностика указывает точный индекс эпизода.
- Результат ограничен теми же 20 MiB, что и входной RSS: CLI не создаёт файл, который не сможет прочитать следующим запуском.
- FIFO отклоняется без блокирующего открытия; изменения файла во время чтения выявляются; BOM сохраняется в снимке исходных байтов.

## Полнота Podcasting 2.0

Сверены **31 действующий тег и устаревший images** из [зафиксированной спецификации](SOURCES.md). Набор тегов уже был представлен; обнаруженные пробелы относились к корректности значений, контекстов и связанных условий.

- RRULE: добавлены проверки реальных календарных дат, времени, комбинаций BY*/FREQ, COUNT/UNTIL, date/datetime и UTC для UNTIL при зональном DTSTART.
- BCP 47: принимаются допустимые private use, grandfathered и extlang; повторные варианты/extension-singletons отклоняются.
- geo URI: проверяются высота, порядок и уникальность параметров, неотрицательная погрешность и диапазоны WGS84.
- image/images: принимаются пустой alt, литеральные CSS-отношения/auto, запятые внутри URL srcset; проверяются повторные и смешанные дескрипторы.
- integrity: SRI принимает base64url и options; проверяется длина и корректность кодирования хеша.
- medium: проверяются обязательные remoteItem/guid для publisher и состав list-фидов.
- Числа вроде `suggested: 0.00000005` сериализуются десятичной дробью: собственный валидатор больше не отвергает результат из-за экспоненты JavaScript.
- Необычные имена атрибутов, включая `__proto__`, сохраняются и диагностируются, а не теряются при преобразовании входного объекта.

Границы остаются явными: [справочник](PODCASTING2.md), [источники](SOURCES.md). Утверждённый набор тегов поддержан целиком, но это не гарантия полной семантической проверки любого значения: CSS-функции не вычисляются, календарь RRULE не разворачивается, внешние файлы и криптографическая достоверность не проверяются. Отдельные publisher/list-фиды не являются аудиоподкастом с выпусками и не проходят общий профиль платформ.

## Проверка

Регрессии находятся в [test/review.test.mjs](../test/review.test.mjs), базовые сценарии — в [test/feed.test.mjs](../test/feed.test.mjs) и [test/cli.test.mjs](../test/cli.test.mjs).

```sh
npm ci
npm run check
```

Проверки охватывают положительные и отрицательные примеры XML/Podcasting 2.0, CLI, стабильность GUID, сохранение старых элементов, backup, конкурентные записи, изменение файлов во время подготовки и ошибку fsync после фиксации результата. Сбои и конкурентные изменения воспроизводятся детерминированно без удалённых медиа.

Атомарная замена и lock защищают взаимодействие экземпляров CLI. Для сторонних редакторов нужна внешняя координация: переносимый файловый API не предоставляет атомарной операции «сравнить содержимое и заменить», поэтому между последней проверкой и rename остаётся короткое окно гонки. Удалённый RSS фиксируется на момент загрузки; CLI не обновляет и не блокирует серверную копию.
